## Conventions that must not break
- **Commit + push after every response** (user requirement — see CLAUDE.md).
- Every UI string goes through `t()`, added to BOTH `en` + `nl`.
- Work is "done" only when both apps typecheck + server bundles (unless a quick fix).
- 0-euro budget everywhere, no free trials.
- **Schema drift trap:** `lib/auto-migrate.ts` only does `CREATE TABLE IF NOT EXISTS` + `ADD COLUMN IF NOT EXISTS` — it NEVER alters existing column types. A schema change to an existing column (e.g. `llm_keys.scopes` `jsonb` → `text[]`) leaves the live DB stale silently and breaks inserts with `invalid input syntax for type json` while nothing else errors (2026-09-11, api-key POST 500; fixed live by shadow-column rebuild). When changing an existing column's type in `lib/db/src/schema/`, ALTER the live table too.
- **False-green trap (guard-shape vs guard-value):** `formatVerificationFeedback` in `lib/structured-tools.ts` returned "All checks passed." on a genuinely broken build because Fix 0.10 made `parseBuildArtifacts` push a `failed:true` marker on non-zero exit — so `buildArtifacts.length > 0` on failure — but the Build Failed renderer gated on `length === 0`. A guard written against the ARRAY'S SHAPE silently breaks the moment that shape changes. When Fix 0.10 changed "failure = no artifacts" to "failure = failed artifact", the sibling code that still tested `length === 0` became dead and handed back a green verdict. **Rule: when a marker/flag is added to a result type, grep every consumer that tests the type's shape (length/empty) and update them in the same change.** Fix: filter `b.failed` first, render each failed artifact's stderr tail, keep the empty-array guard only as a final branch. Verified live via telemetry (0 "All checks passed" / 1 "Build Failed" on broken run; 2026-09-11).
